# 3–5 minute demonstration script (real execution) and recording instructions

**No demo video has been recorded yet.** This is the script to record one. Everything shown must be live output of the running system.

## Before recording (1 minute, off camera)

```sh
uv sync --locked
uv run python scripts/run_local.py --port 8000      # starts 3 A2A agents + web; keep this terminal visible
```
Open `http://127.0.0.1:8000/`. Use a fresh `--data-dir` if you want an empty incident history.

## Recording sequence

| time | show | what to say (facts only) |
|---|---|---|
| 0:00–0:30 | Terminal with the 4 started processes and their ports; browser header pills (DB ready, transport a2a, 3 agents available). | Three specialists are separate processes reached over A2A JSON-RPC with a per-run token; the coordinator is not a specialist. Data mode is shown on every incident; this demo uses synthetic data. |
| 0:30–1:15 | New incident -> `S01-congestion` -> Create & diagnose. Diagnosis tab: status, support category, root cause, supporting evidence (click one row: observation + raw record). | Each number is a stored observation with unit and provenance; support is a documented category, not a probability. |
| 1:15–2:30 | New incident -> `S11-ambiguous-resolvable` with verification on. Show Timeline (CORRELATING -> VERIFYING -> CORRELATING), Verification tab (challenges, agent, outcome, new observations), Agents & A2A tab (A2A task ids; click one to show the exact NDEP artifact), Hypotheses tab (contradicted vs confirmed). | Initially only probes were uploaded: congestion, interface fault and CPU overload fit equally. The planner asked specific agents for discriminating data; they returned recorded records unchanged; congestion and CPU were ruled out, CRC errors confirmed the interface fault. |
| 2:30–3:00 | Optional contrast: `S16-ambiguous-unresolvable` -> result stays **ambiguous**; verification outcomes `unavailable`. | When no evidence exists, the system says so instead of guessing. |
| 3:00–3:40 | `S12-malformed-mixed` (or Upload tab with `spec/profiles` CSV via S13). Evidence tab: rejected records with typed codes (MISSING_UNIT, MISSING_TIMEZONE, TYPE_MISMATCH, UNKNOWN_SUBJECT quarantine, stale). | Bad inputs are rejected or quarantined with reasons; the diagnosis still works on valid data and lists the limitations. |
| 3:40–4:20 | In the launcher terminal stop nothing; instead run in a second terminal `uv run pytest tests/integration/test_a2a_agents.py -k crash -q` **or** show a report from a run where an agent was unavailable (coverage + limitations). | Agent failure is reported as missing coverage, never as a fabricated reply. |
| 4:20–5:00 | Topology tab (root cause red, affected orange); download JSON report; show `eval/results/RESULTS.md` table; end with repository URL and `uv run pytest`. | Results are generated by `scripts/evaluate.py`; the held-out set was generated after freezing the rules; synthetic data and same-author generator are stated limitations. |

## Recording tips

- Windows: Xbox Game Bar (`Win+Alt+R`) or OBS Studio; record the browser and terminal side by side at 1080p.
- Do not edit results; cuts are fine only between steps, never inside a step that shows output.
- Mention once that no live campus network is accessed.
